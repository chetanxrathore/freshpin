# Write-time audits close agents' stale-version gap

No existing tool does what freshpin does in one place. Freshpin looks up the latest stable versions live and audits a file at the moment an agent writes it. It checks four things: libraries, GitHub Actions, Docker base images, and whether a runtime or database has reached end-of-life (EOL). It covers Python, npm, Rust, workflow, Dockerfile and compose files, with zero dependencies. The problem is measured, not anecdotal. Across 10 early-2026 models, the median pinned PyPI version was 9–31 months older than the model's own knowledge cutoff, and 36.7–55.7% of pinned versions had a known CVE. Injecting looked-up versions into the prompt cut CVE exposure by roughly 60–75%; telling the model in plain language to be careful did almost nothing. The existing tools split into five camps, each solving a slice: dozens of version-lookup MCP servers that agents rarely call unless prompted; a handful of tiny Claude Code hooks that check exact pins only, only warn, or focus on security; vendor security servers (Sonatype, Snyk, Socket, Endor) that recommend the "safest" version rather than the newest and need an account; mature pull-request bots and CLIs (Renovate, Dependabot, ncu, taze, uv) that act after the commit or need each ecosystem's toolchain; and Actions, Docker and EOL tools that pin or lint but rarely say a newer major or LTS release exists. The closest overlaps are AndrewTtofi/versions, KTH's yul, pinact's agent skill, taze and arhancanli's end-of-life-mcp, and each misses at least two of freshpin's four file families. Freshpin's lead is real but thin. The ecosystem has moved to a 3-day release-age wait ("cooldown") by default, to SHA pins, to GitHub's native `actions.lock` (generally available since 28 October 2026), and to "latest" meaning latest compatible with the project's constraints. Freshpin handles none of these yet, so the most valuable additions are a cooldown, compatibility-aware selection, pin-style and lockfile awareness, explicit "this version does not exist" detection, coverage of shell installs, hook ports to Codex, Copilot and Gemini CLI, and a published benchmark of stale Actions and Docker pins, which no study has yet measured.

## Models pin versions 9–31 months stale, and only injected facts fix it

The best direct measurement is the May 2026 PinTrace preprint. It tested 10 early-2026 models, including GPT-5.4, Claude Sonnet 4.6, Gemini 3.1 Pro, DeepSeek-V3.2, Qwen3.5 and Llama-4-Scout, on 1,000 Python tasks. **The median version a model specified was released 9 to 31 months before that model's own knowledge cutoff**, and the lag did not shrink with model size or recency ([arXiv 2605.06279](https://arxiv.org/html/2605.06279v1)). Staleness is a security problem as much as a hygiene one. **36.7–55.7% of model-specified versions had at least one known CVE, and 72–91% of those CVEs were public before the cutoff** ([arXiv abstract](https://arxiv.org/abs/2605.06279)). So a newer cutoff does not fix the problem: models reproduce the popular versions in their training data, not the newest version they knew about. The same study found that **11.23% of version strings resolved to no published PyPI release at all, and 91.96% of those were invented version numbers** such as `opencv-python==4.8.0`. Models also wrote a version into manifests only 6.45–59.19% of the time, leaving the rest to whatever resolves at install ([arXiv HTML](https://arxiv.org/html/2605.06279v1)). Vendor studies point the same way, with less transparent methods. Sonatype found **GPT-5 named versions that do not exist in 27.76% of 36,870 upgrade recommendations** ([Sonatype 2026](https://www.sonatype.com/state-of-the-software-supply-chain/2026/ai-agents)). A Sonatype follow-up across seven models found the rate fell roughly 4x, but the best model working without live data still invented about 1 version in 16, and Claude Opus 4.6 reached 32.0% on an adversarial sample ([Sonatype research](https://www.sonatype.com/resources/research/making-ai-work-safely)). Endor Labs reports 34% non-existent and 49% vulnerable versions from AI agents, without disclosing models or prompts ([Endor Labs](https://www.endorlabs.com/learn/state-of-dependency-management-2025)).

Package names go wrong too, not just versions. The peer-reviewed USENIX Security 2025 study by Spracklen et al. found **19.7% of 2.23 million package references from 16 models named packages that do not exist**. The rate was about 5.2% for commercial models and 21.7% for open models. **43% of the invented names came back in all 10 re-runs**, which makes them predictable names an attacker can register ([arXiv 2406.10279](https://arxiv.org/html/2406.10279v3)). Prompts anchored to a date, such as "a library from 2025", push invented libraries as high as 85% of tasks ([Twist et al., EMNLP 2026](https://arxiv.org/abs/2509.22202)). Generated CI configuration names CI-plugin versions that do not exist 2.22–9.12% of the time ([Li & Gao](https://arxiv.org/html/2509.20277v1)). In real pull requests, a Purdue study of 33,596 agent-authored PRs found agents picked known-vulnerable versions for **2.46% of the dependencies they introduced, against 1.64% for humans**. 36.8% of the agents' vulnerable picks needed a major-version jump to fix, against 12.9% for humans ([arXiv 2601.00205](https://arxiv.org/html/2601.00205v1)). Older codebases make it worse: ICSE 2025 work found deprecated-API usage of 70–90% when the surrounding code was already outdated, against 9–18% with up-to-date code ([arXiv 2406.09834](https://arxiv.org/html/2406.09834v3)). And the human code agents learn from is itself stale: Datadog's 2026 telemetry puts **the median dependency 278 days behind its latest major, with 10% of services running an EOL runtime** ([Datadog](https://www.datadoghq.com/state-of-devsecops/)).

The failures freshpin targets most directly, in workflows and containers, are silent until CI runs. GitHub removed Node 20 from Actions runners on 24 September 2026, the second forced runtime migration in three years. That means action major versions learned from 2024-era data now point at runtimes GitHub has removed ([GitHub changelog](https://github.blog/changelog/2026-09-24-node-20-is-no-longer-available-in-github-actions/)); `actions/checkout` is now at v7.0.1 ([releases](https://github.com/actions/checkout/releases)). In Microsoft's November 2026 stale-docs experiment, Claude Haiku 5.5 wrote `version: 4.0.0` without the required `v` prefix in 3 of 12 runs and declared the workflow finished; the error only shows up as a 404 in CI ([summary of the Microsoft study](https://windowsforum.com/news/microsoft-tests-how-stale-documentation-affects-ai-coding-agents-in-vs-code.454055/)). Microsoft separately documented `npx` silently installing a July 2020 SPFx release instead of v1.23.0, because the newer release's `engines` field excluded the active Node version ([Microsoft](https://developer.microsoft.com/blog/your-agent-just-scaffolded-a-project-from-2020/)). Aikido traced a made-up `npx react-codeshift` command, written into LLM-generated agent skills, to 237+ repositories ([Aikido](https://aikido.dev/blog/agent-skills-spreading-hallucinated-npx-commands)). Freshpin's own corpus run hints at why agents pick up these habits. Of 579 declarations in GitHub's `actions/starter-workflows`, freshpin flagged 447 as outdated, and 139 of 233 in `docker/awesome-compose`; both are template repositories that agents learn heavily from. These figures come from a local run under freshpin's own policy and have not been independently validated (`validation/results/corpus.md`).

The evidence on mitigations is unusually consistent: **inject looked-up facts; do not ask the model to be careful.** In PinTrace, feeding pre-computed safe versions into the prompt cut CVE exposure from 40.51% to 9.98% for GPT-5.4 and from 38.58% to 11.99% for Claude Sonnet 4.6. It also raised the share of Sonnet's dependency sets that passed a static compatibility check from 16.16% to 90.48%. A plain-language "avoid vulnerable versions" instruction moved exposure by at most 2.2 points, and *raised* Sonnet's to 46.55% ([arXiv HTML](https://arxiv.org/html/2605.06279v1)). Sonatype reports GPT-5 Nano's rate of invented versions falling from 88.9% to 6.8% when the model had a live version-lookup tool ([Sonatype research](https://www.sonatype.com/resources/research/making-ai-work-safely)). Context7's own benchmark cut answers that used only old APIs from 43 of 94 to 9 of 94 with a docs tool ([Context7](https://context7.com/guides/why-ai-coding-agents-use-outdated-apis)). pinright's self-run test dropped pins with known advisories from 40–42% to 0% using a hook that checks install commands before they run ([pinright](https://github.com/Hiper-AI/pinright)). Two cautions temper "always latest". First, Sonatype found the "latest version" strategy gave the largest security gain (+267.1%, against +120.4% for the LLM's own picks), but it cost about $29,516 and 314 developer-hours per app; the LLM's picks also included compromised releases published after its cutoff, such as color 5.0.1 ([Sonatype](https://www.sonatype.com/state-of-the-software-supply-chain/2026/ai-agents)). Second, William Woodruff's review of 10 supply-chain attacks found 8 with exploitation windows under a week, which is the core argument for waiting a few days before adopting a new release ([nesbitt.io](https://nesbitt.io/2026/03/04/package-managers-need-to-cool-down.html)). The evidence also has holes. PinTrace covers PyPI only, with single-turn prompts. **No study measures how often agents write outdated Action major versions or EOL Docker base images**, a gap a freshpin benchmark could fill.

## Dozens of version MCP servers exist, and agents rarely call them unprompted

MCP servers that return a package's latest version are now a crowded but fragmented category. Searching the official MCP Registry returns 44 entries for "version", 56 for "dependency" and 19 for "endoflife". Many are noise (the search is a substring match), and many are hosted endpoints with no public repository ([MCP Registry](https://registry.modelcontextprotocol.io/v0/servers?search=dependency)). The best-known project, sammcj/mcp-package-version (120 stars), is archived and has been folded into the larger mcp-devtools ([GitHub](https://github.com/sammcj/mcp-package-version)). The broadest one, MShekow/package-version-check-mcp, has 9 stars and concedes that "Most LLMs don't automatically invoke this MCP's tools without explicit guidance" ([README](https://github.com/MShekow/package-version-check-mcp)). Nearly all of them answer questions about packages the agent names; they do not read the project's files. That pull model, where the agent must decide to ask, is the category's central weakness.

Documentation MCPs answer a neighbouring question and dominate adoption. **Context7 has about 65,000 stars and 4.3 million npm downloads a month.** It matches docs to a version you name in the prompt, but it does not report what the current version number is ([GitHub](https://github.com/upstash/context7), [npm](https://www.npmjs.com/package/@upstash/context7-mcp)). ## Hooks, skills and rules: the enforcement layer is tiny and mostly security-first

Claude Code hooks that check freshness at write time do exist, but they are research prototypes or small community projects. **yul**, from KTH's CHAINS research project, is the closest analogue to freshpin. It is a `PreToolUse` hook on Write/Edit that blocks an outdated exact pin (exit 2) and tells Claude the current version. It covers Maven, PyPI, npm, Cargo, go.mod and workflow tags, but not Dockerfiles or EOL. Across 20 scaffolding prompts it fired 9 times. It **missed 8 cases that used version ranges, and 3 where `npm install` ran through Bash, so no file edit ever passed through the hook** ([KTH CHAINS](https://chains.proj.kth.se/ai-bump.html)). It has 3 stars and is MIT-licensed Go ([GitHub](https://github.com/chains-project/yul)). **Version Sentinel** hooks manifest edits and install commands. A blog post described it blocking edits until a version check was recorded, but its current README says "Hooks never block tools". That retreat from blocking suggests the friction was too high ([GitHub](https://github.com/KSEGIT/Version-Sentinel), [DEV post](https://dev.to/ksegit/i-built-a-claude-code-plugin-that-blocks-hallucinated-package-versions-55mg)). It has 6 stars, an MIT licence, and no Actions, Docker or EOL support. **safer-dependencies** is the most complete hook bundle, but it is built for security. After Write/Edit it rewrites risky versions in place. Before a Bash install it blocks known-vulnerable versions, after one it scans lockfiles, and a separate hook pair covers files written by subagents. It picks the newest stable version at least 7 days old and checks it against OSV, across npm, PyPI, RubyGems, Maven, Go, Rust and PHP. It has 43 stars and a source-available, non-OSI licence ([GitHub](https://github.com/robert-auger/safer-dependencies)).

Skills and plugins in this space mostly advise rather than enforce. **retlehs/gh-actions** is a SKILL.md listing "current versions" for workflows, installable in "30+ agents". It hard-codes those versions with no way to refresh them, so it goes stale with every release ([GitHub](https://github.com/retlehs/gh-actions)). The **Dependency Updater** skill in davila7's claude-code-templates shells out to `taze`, `pip list --outdated`, `cargo outdated` and similar. NVIDIA's SkillSpector scanner scored it **27/100**, flagging its unpinned `npx taze` call and "excessive agency" ([aitmpl](https://www.aitmpl.com/component/skills/development/dependency-updater)). **pinact now ships its own agent skill** (`gh skill install suzuki-shunsuke/pinact pinact`), which competes directly for the GitHub Actions freshness slot ([pinact](https://github.com/suzuki-shunsuke/pinact)). Anthropic's official plugin directory (48,200 stars) showed no dependency-freshness plugin ([GitHub](https://github.com/anthropics/claude-plugins-official)).

Rules files are the most common approach and the weakest. The typical rule says "never guess versions; query the registry first" and lives in `.cursor/rules`, `.github/copilot-instructions.md`, `AGENTS.md`, `.windsurf/rules` or `.junie/AGENTS.md`. Snyk's own documentation says rules "don't install hooks or guarantee that scans run" ([Snyk](https://docs.snyk.io/integrations/snyk-studio-agentic-integrations/snyk-studio-and-secure-at-inception)). A Classmethod test found a CLAUDE.md instruction depended on the model choosing to follow it, while a hook blocked reliably ([Classmethod](https://dev.classmethod.jp/articles/snyk-studio-claude-code-mcp/)). Context7 warns that version facts written into rules files go "stale with each release" ([Context7](https://context7.com/guides/why-ai-coding-agents-use-outdated-apis)). Microsoft's .NET team advises pointing instructions at sources of truth such as `global.json` instead of restating versions ([Microsoft](https://devblogs.microsoft.com/dotnet/instructions-hygiene-what-frontier-models-still-need-you-to-say)). In Microsoft's stale-docs study, agents "often noticed that two pages disagreed and still followed the outdated one" ([summary](https://windowsforum.com/news/microsoft-tests-how-stale-documentation-affects-ai-coding-agents-in-vs-code.454055/)). PinTrace's finding that safety instructions did nothing, and sometimes made things worse, is the strongest quantitative version of the same point.

Hooks that run after an edit are now nearly universal, and most can send text back to the model, so freshpin's hook should port cheaply:

Skills have standardised faster than hooks. Anthropic released the Agent Skills format (a SKILL.md file plus optional `scripts/`) as an open standard ([agentskills.io](https://agentskills.io/home)). **46 products read it as of August 2026**, and `.agents/skills/` is becoming the path every client checks, next to vendor folders such as `.claude/skills`, `.cursor/skills` and `.github/skills` ([skillsboard](https://www.skillsboard.sh/agent-skills-support)). Socket already ships one skills repository to Claude Code, Codex, Gemini CLI, Cursor and OpenCode ([SocketDev/skills](https://github.com/socketdev/skills)). A skill folder holding a standard-library Python script suits this model better than tools that need a Go binary or `npx`.

## Classic updaters, pinners and EOL scanners arrive after the commit

### Dependency updaters are thorough, reactive and toolchain-bound

Two bots dominate breadth. **Renovate** has 120 built-in file parsers ("managers"), 85 version sources ("datasources"), including one for endoflife.date, and 58 versioning schemes ([managers](https://github.com/renovatebot/renovate/blob/main/lib/modules/manager/api.ts), [datasources](https://github.com/renovatebot/renovate/blob/main/lib/modules/datasource/api.ts)). **Dependabot** supports 34 ecosystems, including github-actions, docker, docker-compose, pre-commit and uv ([options reference](https://docs.github.com/en/code-security/dependabot/working-with-dependabot/dependabot-options-reference)). Both run as scheduled pull-request bots. Everything else is a single-ecosystem CLI that needs its own toolchain, and often a lockfile or an installed environment. Most emit JSON in well under a second when their toolchain is present, so speed is not the barrier for agents. Setup and coverage are.

| Tool | Scope | How it runs | License | Popularity and activity | Fit for use inside an agent's edit loop |

Waiting a few days before adopting a new release ("cooldown" or "minimum release age") became the default in 2025–2026. Dependabot has applied a 3-day default to version updates on github.com since 14 July 2026, with security updates exempt ([changelog](https://github.blog/changelog/2026-07-14-dependabot-version-updates-introduce-default-package-cooldown/)). Renovate's security presets use 3 days for npm, crates and PyPI ([preset](https://github.com/renovatebot/renovate/blob/main/lib/config/presets/internal/security.preset.ts)). Package managers now have native settings for it: npm `min-release-age`, pnpm `minimumReleaseAge`, uv relative `exclude-newer`, Poetry `solver.min-release-age`, pip `--uploaded-prior-to` and pdm `--exclude-newer` ([Renovate](https://docs.renovatebot.com/key-concepts/minimum-release-age/), [Poetry 2.4.0](https://python-poetry.org/blog/announcing-poetry-2.4.0/)). Cargo's equivalent is still behind an unstable flag ([RFC 3923](https://rust-lang.github.io/rfcs/3923-cargo-min-publish-age.html)). ncu's behaviour fits authoring time best: when the newest release is still inside the waiting window, it falls back to the newest version that has passed it, instead of skipping the package ([ncu](https://github.com/raineorshine/npm-check-updates)).

Renovate's stability rules are the best open reference for what "latest stable" should mean. `respectLatest` never goes past the registry's `latest` tag, `ignoreUnstable` skips prereleases, `ignoreDeprecated` skips deprecated versions, and `rangeStrategy` (`pin`, `bump`, `replace`, `widen`) keeps the project's existing constraint style ([respectLatest](https://docs.renovatebot.com/configuration-options/#respectlatest), [ignoreUnstable](https://docs.renovatebot.com/configuration-options/#ignoreunstable), [rangeStrategy](https://docs.renovatebot.com/configuration-options/#rangestrategy)). uv adds a correctness detail freshpin should copy: it reports the latest version *compatible with the project's `requires-python`*. One test project declaring Python `>=3.10` was told fastapi 0.162.5 was latest, because 0.162.6 onwards requires Python 3.11 ([PyPI](https://pypi.org/pypi/fastapi/0.162.6/json)). GitHub's main AI move is still after the fact: Dependabot *security* alerts can be assigned to Copilot, Claude or Codex, which open draft fix PRs. This requires GitHub Code Security and does not cover routine version updates ([changelog](https://github.blog/changelog/2026-04-07-dependabot-alerts-are-now-assignable-to-ai-agents-for-remediation)).

### GitHub Actions tools pin and lint, but few say "a newer major exists"

GitHub Actions tooling splits three ways. Pinners and updaters rewrite the `uses:` lines in workflows. Pull-request bots bump them on a schedule. Linters and GitHub's own policy controls enforce pinning but **do not** say a newer major version exists.

Three facts change what a correct Actions suggestion looks like. Since 15 August 2025, org admins can require every action to be pinned to a SHA, and an unpinned reference then fails when the job starts, after the PR has already merged ([changelog](https://github.blog/changelog/2025-08-15-github-actions-policy-now-supports-blocking-and-sha-pinning-actions/)). zizmor now flags any reference that is not a SHA, including GitHub's own `actions/*`. And in a workflow that uses `actions.lock`, "each dependency... must be in the lockfile". In a growing share of repositories, then, a bare `@v7` suggestion is wrong. The right output is `@<sha> # v7.0.1` plus an instruction to regenerate the lock. Rate limits matter as well. The GitHub REST API allows 60 requests an hour without a token, and the research session's shared-IP quota ran out after about 25 lookups. By contrast, `git ls-remote` listed every `actions/checkout` tag in 0.34 seconds without touching that quota, which is the same token-free path freshpin uses.

### Docker and EOL tools watch digests and OS layers, not declared majors

Only Renovate and Dependabot propose newer base-image *tags*. Renovate keeps the tag's variant suffix, so a `-alpine` user is never offered a non-alpine tag, and keeps its precision, so `12.14` moves to `12.15`, not `12.15.0`. It calls Docker tags a "wild west" and offers a looser comparison mode as the escape hatch ([Renovate Docker versioning](https://docs.renovatebot.com/modules/versioning/docker/)). The other well-known tools measure something else. **Docker Scout**'s "No outdated base images" policy checks whether the base tag now points at a different image than the one you built from (digest drift), not whether a newer major exists, and it needs provenance attestations from the build ([Docker Scout](https://docs.docker.com/scout/policy/)). **Snyk Container** recommends minor, major or alternative base images based on vulnerability counts, but precomputes recommendations only for Docker Official Images ([Snyk](https://docs.snyk.io/scan-fix-and-prevent/scan-with-snyk/snyk-container/use-snyk-container/detect-the-container-base-image)). **hadolint** only warns about a missing tag or `latest` (rules DL3006 and DL3007) ([hadolint](https://github.com/hadolint/hadolint)), and **diun** sends a notification when an image changes but edits nothing ([diun](https://github.com/crazy-max/diun)). **Watchtower** (24,575 stars) was **archived on 17 December 2025** ([Linuxiac](https://linuxiac.com/docker-update-tool-watchtower-reaches-end-of-maintenance/)).

For hardened images, Docker made its Hardened Images catalog free under Apache-2.0 in December 2025, while Chainguard's free tier still serves only `:latest` ([Docker](https://www.docker.com/blog/docker-hardened-images-for-every-developer/), [Chainguard](https://chainguard.dev/unchained/changes-to-chainguard-images-developer-tier)). Docker Hub's rate limits are not fully clear. The docs cap anonymous pulls at 100 per 6 hours per IP ([Docker docs](https://docs.docker.com/docker-hub/usage/)). A registry probe on 26 November returned a header of `100;w=3600`, a 1-hour window. The Hub tags API returned `x-ratelimit-limit: 180` and supports `name=` filtering ([Hub API](https://hub.docker.com/v2/repositories/library/python/tags?page_size=3&name=3.15-slim)).

endoflife.date is the standard source for EOL data. It covers 490 products (API schema 1.2.1) and is served from Netlify's CDN with no rate-limit headers ([products](https://endoflife.date/api/v1/products)). Each product lists identifiers such as `pkg:docker/library/postgres` that map Docker image names to products ([postgresql](https://endoflife.date/api/v1/products/postgresql)). The API is still labelled Beta ([repo](https://github.com/endoflife-date/endoflife.date)), and its data is not perfect: the PostgreSQL 19 entry gives a release date (19 November 2026) later than its latest patch date (16 November), so cross-checking against the registry is prudent. The tools that consume this data stop short of authoring-time audits. **Renovate** reads endoflife.date through comments you add to files, but has **no built-in way to recommend only LTS releases**; the workaround is a custom datasource ([discussion #25363](https://github.com/renovatebot/renovate/discussions/25363)). **norwegianblue** is a well-maintained CLI client (153 stars, v0.27.0 on 25 November 2026) that answers queries rather than auditing files ([norwegianblue](https://github.com/hugovk/norwegianblue)), while **xeol** (453 stars) has not released since March 2025 ([xeol](https://github.com/xeol-io/xeol)). **Trivy and Grype** flag only EOL OS distributions inside images that have already been built ([Grype](https://oss.anchore.com/docs/guides/vulnerability/eol-detection/), [Trivy](https://github.com/aquasecurity/trivy/discussions/4263)).

Node.js has also changed its release model. From v27, every major becomes LTS after an October promotion, with an alpha phase from October to March. That breaks the "even number means LTS" rule many tools, and models, assume ([Node.js](https://nodejs.org/en/blog/announcements/evolving-the-nodejs-release-schedule)). Node's release index already lists `v27.0.0-alpha` first ([dist index](https://nodejs.org/dist/index.json)), so naive "take the newest" logic would pick an alpha. No tool found checks a declared `FROM postgres:14`, `node-version: 18` or `.python-version` against EOL and LTS data while the file is being written.

**Freshpin's main differentiator is the combination.** No other tool found covers package manifests, workflow `uses:` lines and runtime inputs, Docker and compose images, and LTS-aware EOL together, and none does it at the moment the agent writes the file. It also catches exactly the case Socket's install hook documents as invisible to it: a manifest edit followed by a bare install. It reasons about version ranges, not just exact pins. It flags `^18.2.0` once React 19 ships and a `>=0.100` minimum once 0.165 is out, which closes yul's largest miss category. And it is the only lightweight option that needs nothing beyond Python. Every other lightweight competitor requires Node, Go, jq, Docker or a hosted account, and freshpin avoids the unpinned-`npx` problem SkillSpector flagged in a competing skill.

Several smaller design choices map directly onto documented failures. **Token-free GitHub lookups** read tags through git's public smart-HTTP endpoint, so freshpin does not hit the 60-requests-an-hour limit that stalls taze and actions-up without a token, and for SHA-pinned workflows the same tag list yields the exact replacement SHA. **Docker tag checks** confirm a suggested tag actually exists on Docker Hub; freshpin's own validation caught a naive `elasticsearch:9.5` suggestion that does not exist (`validation/results/accuracy.md`). **Date-based LTS** recommends the newest release whose LTS date has already passed, which already copes with Node 27's new model, where Renovate needs a custom datasource. **Edit-scoped reporting** flags only the lines an Edit wrote, so a deliberate old pin elsewhere in the file does not nag. **One line per finding** keeps token cost low, which matters given pinright's measurement that docs-style context costs roughly 4x the tokens. And the real-world corpus run parsed **12,135 declarations across 18 repositories with no crashes or parse errors**.

**Its gaps cluster around correctness.** First, there is no cooldown, and the default moved in 2026: Dependabot and Renovate's presets wait 3 days, mcp-devtools 72 hours, safer-dependencies and zizmor's recommendation 7 days, and actions-up 1 day. Without one, freshpin steers agents toward releases that are hours old. That is exactly when compromised versions like color 5.0.1 do their damage, and those are also the versions a repository's own pnpm, npm or uv cooldown will refuse to install, or that its bot will hold back. There is an implementation catch: npm's `/latest` endpoint and the git refs path carry no publish dates, so a cooldown needs npm's full package document, which includes a `time` map, plus a release date for each GitHub tag.

Second, "latest" is neither guaranteed stable nor compatible with the project. npm's `latest` tag can point at a prerelease, and freshpin passes it straight through: its own validation run resolved `npm:prisma` to `8.0.0-rc.35`, the case Renovate's `ignoreUnstable` exists for. Freshpin also records the latest release's own Python requirement, but it does not filter candidates against the project's `requires-python`, `engines.node` or `rust-version`. uv does that filtering, and its absence is exactly how Microsoft's `npx` fell back to a 2020 release.

Third, on GitHub Actions, freshpin handles SHA pins that carry a `# vX.Y.Z` comment, but skips bare SHAs. It does not detect `actions.lock`, zizmor's SHA requirement or org-level SHA enforcement, and its default suggestion is a bare major tag, which those repositories reject.

Fourth, the hook matches only Write, Edit and MultiEdit. It misses `npm install x`, `uv add` and `cargo add` run through the shell (yul's 3 Bash misses), manifests and lockfiles rewritten by a package manager, and files written by subagents, which safer-dependencies covers.

Fifth, breadth trails the incumbents. Freshpin has no go.mod, Maven/Gradle, NuGet, RubyGems or Composer support; no `.nvmrc`, `.node-version`, `.python-version`, `.tool-versions` or `rust-toolchain.toml` checks, which taze, Renovate, Dependabot and end-of-life-mcp already cover; no `runs-on` runner-label checks; and no pre-commit config support, which Dependabot has handled since March 2026. On containers it resolves only images that endoflife.date tracks and that live on Docker Hub, skipping other images and anything on ghcr.io, quay.io or mcr, while MShekow and Renovate resolve tags in any registry. Finally, there is no security layer beyond npm deprecation notices; every agent other than Claude Code gets only an advisory AGENTS.md rule; and nothing reads `renovate.json` or `dependabot.yml`, so the agent can write version X and the repository's bot can propose Y the next day.

**The risks are competitive, behavioural and operational.**

*Competition is closing in.* AndrewTtofi/versions, created 30 September 2026, makes nearly the same pitch, adding scheduled PRs and rules files for 17 agents but lacking Actions, Docker and EOL. pinright arrived on 29 October and vigie on 25 November. pinact distributes a skill, taze markets agent-friendly JSON, and Context7 already reaches 4.3 million downloads a month and could add a version field. Sonatype is already "Anthropic verified" in the Claude marketplace. GitHub has shown with lockfiles and agent-assignable alerts that it absorbs workflow-level features. Freshpin's moat is execution speed and correctness, not novelty.

*The "latest" objection is real.* Vendors optimise for the fewest breaking changes, and Sonatype puts the latest-everything strategy at about $29,516 per app. pinright measured 5.9–7.5 agent turns per task with its blocking hook, against 4.0–4.3 without, and freshpin's default `decision: block` will add turns the same way. Version Sentinel's retreat to warnings suggests users tire of blocking. Database majors are the sharpest case: suggesting `postgres:14 -> postgres:19` in a compose file that points at an existing data volume describes a data migration, not a one-line edit.

*The data and network layers are fragile.* Freshpin calls endoflife.date's legacy endpoint (`/api/<product>.json`), while the v1 schema with `isLts`, `ltsFrom` and `isEol` is the maintained path, and both are labelled Beta. The GitHub web endpoints it relies on, the `releases/latest` redirect and `info/refs`, are not documented APIs, and Docker Hub's observed limits conflict with its own docs. In locked-down environments such as Copilot's cloud agent, which firewalls outbound traffic, a hook that fails open would silently stop protecting anything.

*Hook output is a prompt-injection channel.* npm deprecation messages are text written by package publishers, up to 200 characters, and freshpin passes them verbatim into the hook's `reason`, which goes straight into the model's context. npm-sentinel-mcp wraps registry text in `<untrusted_external_content>` tags for exactly this reason ([npm-sentinel](https://github.com/Nekzus/npm-sentinel-mcp)).

*Validation lags the code.* The last accuracy snapshot (02:23 on 26 November) predates the token-free GitHub path and recorded GitHub Actions results for 0 of 20 actions because of rate limits. The agent eval at `evals/template-probe/prompt.md` is still a TODO stub. And the README's ecosystem table and the skill's fallback table still point at the rate-limited `api.github.com`.

Socket, Snyk, Sonatype and Endor own security scoring. And because Renovate is AGPL, any cross-check (an optional `--via renovate` mode, say) should run Renovate as a separate process rather than reuse its code.

## Conclusion

The research changes what "freshness" should mean for an agent tool. In a large share of repositories, "the newest version on the registry" is now the wrong answer. The useful answer is **the newest version this repository can actually install today, that its own cooldown, lockfile and pinning policy will accept, and that its update bot will not immediately revert.** Every incumbent implements a piece of that definition: Renovate's stability rules, uv's `requires-python` filter, pinact's lockfile handling, Dependabot's cooldown. None delivers it inside the agent's edit loop across manifests, workflows and containers. Freshpin is already the closest thing to a reliable freshness source at write time, so its next step is correctness, not more ecosystems. A blocking hook is acceptable only if its suggestions are trustworthy. One that confidently suggests a three-hour-old release, a release candidate, or a tag the lockfile will reject loses that trust.

The window is months, not years. Since late September 2026, at least five agent-time dependency tools have appeared: end-of-life-mcp, AndrewTtofi/versions, pinright, opencurrent.ai's actions-latest and vigie. GitHub has also shipped workflow lockfiles at platform level. Two openings remain unclaimed. The first is evidence: nobody has measured how often agents write `actions/checkout@v3`, `node:18` or `postgres:14`, and freshpin's own corpus run suggests the template repositories agents learn from are mostly stale. The second is enforcement across agents: Codex, Copilot CLI and Gemini CLI now accept post-tool hooks shaped much like Claude Code's, so the same standard-library hook can ship to four agents at low cost. A published benchmark plus hooks in all four agents would make freshpin hard to displace. Without them, it is one of dozens of small tools in a category that bigger players are already entering.
